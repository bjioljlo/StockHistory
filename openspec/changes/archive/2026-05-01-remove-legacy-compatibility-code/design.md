## Context

本次重構清理是 `project-refactoring-and-cleanup` 的最終階段。在先前的重構中，系統已完成模組拆分、職責分離、架構重組，並在所有原有位置保留了 100% 向後相容性介面。這些相容性介面現在已經完成它們的過渡任務，可以安全移除。

目前系統中有 42 處已識別的相容性程式碼，分布在 7 個主要模組中，全部都是單純的轉發/別名，不包含任何業務邏輯。

## Goals / Non-Goals

**Goals:**
- 移除所有向後相容性別名和 Facade 類別
- 更新所有內部程式碼使用新的正確介面
- 移除所有已棄用的警告和註解
- 維持 100% 功能不變
- 確保所有測試繼續通過

**Non-Goals:**
- ✗ 不修改任何業務邏輯
- ✗ 不變更任何功能行為
- ✗ 不進行額外的重構或最佳化
- ✗ 不新增任何功能

## Decisions

1. **移除策略**：採用由下而上的移除順序
   - 先移除最底層 Common 模組的相容性程式碼
   - 接著移除 Service 層
   - 最後移除 Controller 和 View 層
   - 每個階段都執行完整測試

2. **驗證方法**：
   - 靜態分析：檢查所有匯入參考
   - 單元測試：執行完整測試套件
   - 整合測試：驗證主要功能路徑

3. **遷移指引**：
   - 提供完整的遷移對照表
   - 明確標示每個舊名稱對應的新名稱
   - 提供搜尋取代範本

## Risks / Trade-offs

| 風險 | 緩解措施 |
|------|----------|
| 外部程式碼依賴舊介面可能中斷 | 提供明確的變更日誌和遷移指引 |
| 有未被發現的隱藏相依 | 執行完整的程式碼掃描和靜態分析 |
| 移除後發生難以除錯的匯入錯誤 | 分批移除，每批後執行測試 |
| 文件或範例尚未更新 | 同時更新所有相關文件 |

## Migration Plan

1. 階段一：掃描並建立完整的移除清單
2. 階段二：更新所有內部程式碼使用新介面
3. 階段三：移除相容性別名和 Facade
4. 階段四：執行完整測試驗證
5. 階段五：更新文件和遷移指引

**回滾策略**：若發生問題，只需恢復被移除的相容性程式碼即可完全復原。
